# 公众号图文交付

默认样式为普通中文技术文章：16px 正文、约 1.85 行距、一个强调色，段落按意思组织。它是可调整的设计默认值，不是微信官方强制标准。不要用与设备无关的「每段最多三行」替代手机预览。

渲染链为本地 marked（含 marked-cjk-friendly 中文强调扩展）→ highlight.js → juice CSS 内联。保留文字、链接和代码的原始信息，代码高亮不改变可复制内容。原始 HTML 在 Markdown 中作为文本显示，不将外部脚本混进文章。

当前稳定支持标题、段落、粗斜体、引用、列表、GFM 表格、链接、注册图片和带语言的代码块。Mermaid/PlantUML/公式源必须先转换成静态图片再写入文章；基础 diagram 命令可生成本地步骤图，不宣称具备未实现的任意公式渲染。

操作配图必须注册到 project.assets，正文以 `![说明](asset:id)` 使用。真实截图须附 capture_manifest 并匹配图像哈希；生成的解释图 role=diagram，不能冒充截图。操作教程设 `visual_policy: real_ui_only`，操作说明使用真实截图或实录关键帧，禁止自制示意图。默认封面通过 `cover.wide_asset`、`cover.square_asset` 指定已注册的实际图片，渲染器直接保留图像。用户另行要求的独立推广封面按下述 cover.design 处理，不作为操作证据。成品的 assets.json 列出文件和来源，原图与授权材料在任务中保留。

教程正文以完整页面或完整操作窗口为主图，用箭头和方框帮助定位。不要用大量局部截图替代页面上下文。交付前逐图检查用户名、头像、邮箱、组织及账号 ID、手机号、支付资料、密钥和地址等信息；用不透明遮挡打码，包括背景和边缘露出的身份信息，不能只遮显眼的正文。泛称 Personal 等非身份文字不必遮挡。用 annotate 的 redact 记录处理，不改动真实按钮、金额或完成状态。发布用 assets/ 仅放处理后的配图；需要重放核验的原图留在 source/originals/ 内部证据目录，不用作配图。宽图在手机上缩小后，正文应点明目标的中文名称和相对位置；需要看细节时优先保留可放大的高分辨率原图，局部放大只作补充。本地预览点击图片可放大，并切换原尺寸；放大控件只在预览页，复制的公众号正文不含这些控件或脚本。

用户单独要求推广封面时，可另做标题排版，用 cover.design 指定两张已制作的横/方封面及权利记录，随成品包一同导出；正文的真实截图规则继续执行。封面、推广描述和开头覆盖相同的目标人群，不用某档示例金额代替权益的完整适用范围。

本账号的封面还须直接置于正文开头：`platforms.wechat.include_cover: true`。渲染器在正文首段之前插入横版封面，导出的 wechat.md、正文HTML、离线HTML及剪贴板使用同一位置与实际图像；无需在源稿反复插图，以免重渲染时叠加。首图不加可见图注。项目中的正文证据图仍单独核查，推广封面不会成为真实操作截图。

`init` 已默认启用这项设置及120字符推广描述上限。`verify` 会读取实际正文，检查首图字节与cover-wide.png一致、首图只插入一次、无重复图注；交付首页有封面不能代替正文首图。结果记录在verification.json的cover_in_body中，缺失或未通过时finalize不能交付。

render 输出：

- wechat.md：可继续编辑的正文与元数据。
- wechat-description.txt：文章推广页使用的纯文本描述；本账号要求 120 字符以内，交付回复也直接提供。
- wechat.html：标题、摘要、正文预览和富文本复制按钮。
- wechat-body.html：仅含内联样式正文的 HTML 片段。
- wechat-copy.html：正文图片以实际文件数据内嵌的独立离线 HTML，不依赖 assets/ 或本地服务器。
- cover-wide.png、cover-square.png：独立排版的横/方封面；横版 1200×510 是设计输出，后台裁切需实际核查。
- assets/、assets.json：真实配图和使用顺序依据。

正文首个 H1 由独立标题区承担，避免重复大标题。复制按钮使用已内嵌实际图片数据的富文本，提供 text/html 与 text/plain；剪贴板中的图片 src 不得是 assets/、file:、localhost 或本机 HTTP 路径。Clipboard API 失败时，copy 事件回退也必须写入同一份内嵌图片 HTML。不能将本地 URL 复制成功误报为图片已复制。封面保留独立文件，同时依账号要求进入正文首图；内嵌图片是剪贴板传输数据，并非已经上传微信，后台是否接收、保存需在那里验证。

普通外链按账号支持和用户要求处理。当前渲染器保留链接，不自动将它们变成编号引用；必要时 Codex 在正文加入用户希望的可复制地址或自然的来源说明。用户不想要来源徽章时不叠加徽章，授权要求仍需满足。

正文结尾用于完成文章，不默认追加“规则核查”“操作配图”或制作过程说明。核查日期、出处、处理记录及署名许可放在 research.json、assets.json 和独立的素材署名与许可.md；不因移除正文说明而声称获得了额外授权。

verify 实际检查本地 Chromium 的 360/390/430px 和桌面布局、图片完整性、代码文本与危险链接，并保存首部、中段、结尾以及每个图片/代码块的预览截图。逐图检查用户名、头像、邮箱等身份信息的遮挡，不用技术验证代替人工视觉判断。宽表拆列或改表达，必要时用图配可复制数据，不缩成小字。

verify 还实际点击复制、关闭来源页、阻断来源请求，再用 Ctrl+V 粘贴到独立 contenteditable，逐张比对图片像素，并分别验证 Clipboard API 和 copy 事件回退。只检查剪贴板中存在 img 标签或 data: 字符串不算通过。

另有一项本地检查会移除类名和头部样式表，再检查内联正文、图片与代码。它能发现对外部 CSS 的依赖，不代表已模拟微信全部过滤规则。

最终文章与排版包可直接交给用户使用。上传公众号、保存草稿、保存后读回、真机预览和公开发布是不同状态，未执行的保持未执行。用户要求接入后台时核查当前官方接口和账号权限，再选择 API 或浏览器；基础成品流程无需账号或密钥。
