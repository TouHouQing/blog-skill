# 复用、来源和闭环

本技能从 [video-skill](https://github.com/TouHouQing/video-skill) 的研究与内容实践发展，复用了 collect.py，并将运行助手拆成独立环境。原视频的 TTS、时间轴、字幕、素材占比和视频成品判断不进入默认依赖。

中文编辑参考改编自 [op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh) 的事实保护和上下文编辑方法，固定版本、许可证及修改记录保存在 third_party。排版链借鉴宝玉技能和 doocs/md 的兼容性经验，使用独立的 marked/highlight.js/juice 包和原创主题，不要求启动它们的工作台，不宣称复制了未纳入的能力。

本地 Node 依赖有锁文件；Python 依赖按基础库范围安装，实际运行环境不进入技能发布包。第三方源码或规则实际纳入时保留适用许可证和记录，单纯研究资料不伪称已集成。

每个任务使用一份研究和项目，各平台稿件单独保存。只在图片、来源或正文改变时重新处理对应部分；当前渲染器会整体重渲染一个任务，因此完成后需重新核验。不增加第二套脱节的选题和素材流程。

## 作者反馈

使用 `feedback` 保存实际 before/after 和说明，默认 source=editorial；确为用户反馈时显式 --source user。`brief` 按需读取 profile.json 和有限条近期反馈。工具保存差异，不自动写通用规则。Codex 根据反复出现、语境明确的认可偏好更新作者档案；不要把一次修改、被否定稿或自审结果标成已认可风格。

账号目录在工作区，避免写进技能共享代码。档案可记录：语言、目标读者、主要平台、作者公开名、认可样本、偏好的结构与禁忌实例。用户新要求和当前样本优先。

## 真实表现

`metrics --file` 读取用户提供或授权取得的 JSON：article_id、platform（blog/wechat/post）、observed_at、window_hours、evidence 和非负 counts。evidence 写真实导出/截图/手工记录来源；不提供假数据凑复盘。

同平台、同窗口的观察才适合比较。阅读、收藏、分享、关注和获客分别看，不用一次高阅读证明标题或文风导致增长。数据未获取时保持未知；本地成品并不等于已发布。

闭环为：事实材料 → 写作与平台改编 → 渲染 → 实际核验 → 审稿修正 → 成品交付 → 用户改稿/真实表现 → 下一次 brief。外部发布是按请求增加的能力，缺少账号不阻碍前六步完成。
